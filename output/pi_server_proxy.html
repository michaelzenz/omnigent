Server-Brokered Pi Inference: How It Works

When a Pi session runs in server-brokered mode, model inference traffic is proxied through the Omnigent server so the Pi CLI never touches Databricks credentials directly.

4. Model to Surface Classification

The inference_surface_for_model() function in inference_proxy.py maps each model ID to exactly one of three gateway surfaces:

Model ID patternSurfaceGateway pathPi wire protocol
claude*anthropic/ai-gateway/anthropic/v1/messagesanthropic-messages
gpt*, system.ai.kimi-*, system.ai.glm-*, inkling, qwen3responses/ai-gateway/openai/v1/responsesopenai-responses
databricks-kimi-*, databricks-glm-*, other databricks-*completions/serving-endpoints/chat/completionsopenai-completions
Other system.ai.*MLflow — not supported by the broker
Why spelling matters: system.ai.glm-5-2 goes to the Responses surface, but databricks-glm-5-2 (same model, different alias) goes to Completions. The gateway rejects a model sent to the wrong surface with "API type ... is not supported by ...".

5. Security Properties

graph TB S1["Capability token — random 32-char secret
SHA-256 hashed, never stored in plaintext
Bound to one session+runner pair
Revoked on runner disconnect"] S2["Loopback only — relay binds 127.0.0.1
Not reachable from network
Ephemeral port, process-scoped"] S3["Tunnel token auth — relay adds RUNNER_TUNNEL_TOKEN_HEADER
Server validates: token→runner_id, session→runner match
Session must be host-bound"] S4["Credential isolation — Pi CLI only sees relay URL + capability
Databricks OAuth token resolved server-side
Never exposed to the Pi process"] S5["Workspace origin validation
Must be https://*.databricks.com or *.azuredatabricks.net
No path, query, userinfo, or non-443 port"] S6["Model-surface enforcement
Server parses JSON body, checks model field
Rejects model sent to wrong surface (400)"] S7["Auto-refreshing Databricks auth
_profile_auth caches auth per profile
current_token() refreshes expired OAuth tokens
Server re-authenticates transparently"]

6. Key Files

FileRole
omnigent/host/inference_relay.pyLoopback relay (FastAPI on 127.0.0.1). Authorizes capability, maps path→surface, forwards to server.
omnigent/server/routes/inference_proxy.pyServer-side route. Validates runner, checks model↔surface, resolves Databricks auth, forwards to gateway.
omnigent/inference_proxy.pyShared constants: env var names, inference_surface_for_model() classifier.
omnigent/pi_model_compatibility.pyModel→surface fallback classifier (databricks_pi_surface_for_model), model entry rendering.
omnigent/pi_native_credentials.pyBuilds Pi models.json for native mode (non-brokered). Sets up providers, surface routing, auth commands.
omnigent/host/connect.pyHost process: starts relay, registers runner sessions, injects proxy URL/token into runner env.
omnigent/runtime/workflow.pyRunner-side: reads proxy env vars, translates to Pi harness env (HARNESS_PI_GATEWAY_HOST, auth command, etc.).
omnigent/inner/pi_executor.pyPiExecutor: when server_inference_proxy=true, builds models.json pointing at relay.
