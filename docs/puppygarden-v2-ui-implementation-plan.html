PuppyGarden product design

V2 task-card board and system integration plan

A consolidated, implementation-ready specification for large task cards, editable work, worker routing, shared chat, manager queue holds, stable ranking, bounded completed history, and grouped assets.

One task per card Secretary / Broker preserved Manager and Worker chat P0–P3 priorities Queue-safe editing

1. Final product decisions

These decisions are the contract for V2. Later sections describe how to implement them without changing their semantics.

Board

Large task cards

Each task is one complete, vertically stacked card. Tasks are not compressed into a navigator.

Overview

Markdown status

description is manager-authored Markdown. It supports nested bullets and recent status without a new overview model.

Goal

User editable

goal remains separate from Overview and can be edited inline by the user.

Items

Actionable work first

Show all active items, then at most three recent done items in the current worker scope.

Chat

Shared conversations

Secretary and Broker work as today. Manager and Worker selections reuse their existing conversation IDs.

Cancel

Removed means gone

Cancelled items leave the dispatchable queue immediately and are not visible or editable in the user UI.

Use existing fields where they already express the concept. Show created_at as “Created”; use description for Markdown Overview; do not add started_at or a structured overview column.

The task-item list is independent of worker lanes. Worker selection filters it; assignment controls route it.

Bounded done history

Show every active/nonterminal item, followed by the three most recent done items across the task.

Worker scope

Show active/nonterminal items assigned to that worker, followed by that worker’s three most recent done items.

Sort done items by updated_at DESC, id DESC. Done items are immutable, so their final update is their completion transition; no completed_at column is required for V2.

Cancelled means removed

Cancelled and interrupted are not interchangeable. Cancellation atomically removes the dispatchable queue item, marks the business item cancelled, clears a halt when cancelling a parked item, and removes the item from user-facing reads. The internal record may remain for audit and garbage collection.

Worker assignment dropdown

If worker_id is null, the closed control displays No worker specified. That phrase is display-only and is not selectable.

Queue-safe instruction and assignment editing

Opening the instruction editor or worker dropdown acquires a hold on that queued item. Earlier queue items may dispatch; the held item cannot dispatch, and later task items do not overtake it. Regular ChatPage messages remain untouched.

Existing not_before is not an edit lock. The current dispatcher filters future items before choosing the oldest eligible item, so a later item could overtake an edited item. Use a dedicated lease that blocks at the FIFO head.

Secretary and Broker

  • Retain the existing Secretary/Broker dropdown and persisted last role.
  • Manager or Worker temporarily overrides the regular role chat.
  • Dismissal returns through today’s dismissToRole(), not always to Secretary.
  • No redesign of the regular role chat is required.

Shared ChatPage conversation path

The current sidebar receives an existing conversation ID, calls useChatStore.getState().switchTo(sessionId), and renders the same blocks and pending messages through MainAgentSurface. Therefore messages sent in regular /c/{conversationId} sessions and messages sent in the PuppyGarden sidebar share one persisted transcript. Add regression coverage; do not add a copying API.

Manager selection hold

Manager is special: selecting it temporarily stops new agent-queue items from dispatching to that task’s manager. A running manager turn continues, and regular ChatPage messages are unaffected.

Click ManagerShow loading state; do not switch chat yet.
Acquire holdTask-scoped manager queue, tokenized and expiring.
Open chatOnly after the backend acknowledges the hold.
Inspect safelyNo new manager system item dispatches.
Leave ManagerRelease hold and wake the queue.

Do not implement this by blindly toggling the persistent queue state. A temporary tokenized hold must not accidentally resume a queue that was manually paused or halted before selection.

UI propagation is not execution pausing

Interactive controls still stop click propagation where needed to avoid a worker/manager selection immediately bubbling to the board dismissal handler. This only prevents an accidental UI target switch; it does not pause a queue. Backend holds occur only for Manager selection and queued item editing.

5. Queue ordering and scrolling

Ordinary updated_at is audit metadata and changes for non-actionable edits. A dedicated sparse rank expresses board order.

Rank model

tasks.queue_rank BIGINT NOT NULL

ORDER BY queue_rank DESC, id DESC
  • New task: MAX(queue_rank) + 1.
  • New task item: move parent task to MAX(queue_rank) + 1.
  • Retrying interrupted/failed work does not change rank; it remains the same task item.
  • Move to queue end: MIN(queue_rank) - 1.
  • Goal, Overview, worker assignment, priority, chat, and asset edits do not affect rank.
  • Double advancement during create-then-add-item is harmless and accepted.
  • Gaps are intentional. Signed 64-bit BIGINT provides ample range.
  • Concurrent duplicate ranks are acceptable; task ID is a deterministic tie-breaker.

Background reorder: preserve reading position

When polling, refetch, or another task receiving work changes ordering, preserve the topmost visible card at the same pixel offset. Record its task ID and relative top before render, then compensate scrollTop in useLayoutEffect. Disable native overflow-anchor for this container and do not animate reordering.

Explicit Move to queue end: successor replaces the card

Move upper visible card 
Before        After
A ← move      B
B             C
C             …
              A ← end

B takes A’s former slot; C enters the viewport.

Move lower visible card 
Before        After
A             A
B ← move      C
C             …
              B ← end

A remains fixed because it precedes B; C replaces B.

  • The moved card intentionally loses its anchor.
  • Cards before it stay in place; its immediate successor fills the vacated slot.
  • Blur the Move button before reordering so browser focus does not follow it to the bottom.
  • For keyboard use, focus the successor with preventScroll: true.
  • Disable the action when the card is already last.

6. Assets and Workers sidebar

There is no “Context” heading. The third card column directly presents the Assets / Workers tabs.

Keep both kind and category

kind: representation

Determines how the asset opens or renders. V2 currently uses url; future kinds may include file, image, or generated artifact.

category: grouping

Determines the always-expanded stack: code, tests, documents, logs, or other.

  "category": "tests",
  "title": "Focused upload suite",
  "url": "https://example.test/run/542"

Asset interactions

  • All category stacks remain expanded; there is no disclosure interaction.
  • Clicking a URL asset’s title opens it directly in a new tab with noopener noreferrer.
  • An × at the right removes the asset through the existing DELETE route.
  • The current frontend already opens URL titles and deletes assets; preserve those behaviors while grouping rows.
  • Add the existing DELETE route to puppygarden/docs/API_REFERENCE.md.

Lease requirements

  • Opaque token, owner/user validation, short TTL, optional heartbeat, idempotent release.
  • Reject acquisition if the queue item already dispatched.
  • Release and wake the dispatcher on save, cancel, expiry, navigation, or component teardown.
  • A manager hold blocks only new manager agent-queue dispatch; an in-flight turn continues.
  • Temporary holds must be additive to persistent queue state, never silently resume an existing manual pause/halt.

Chat state

Keep PuppyGardenChatContext.target as the single source of truth. Worker filtering is derived from a worker target for the same task. Do not create a second independent selected-worker store.

const selectedWorkerId =
  target.kind === "worker" && target.taskId === task.id
    ? target.workerId
    : null;

Data layer

  • Expand agentTasksApi.ts types for priority, rank, category, active items, and recent done buckets.
  • Add hooks for task patch, item create/edit, edit leases, worker assignment, move-to-end, and manager holds.
  • Optimistically update goal, description, and instruction text; roll back on failure.
  • Do not optimistically create a worker until provider/host/workspace validation succeeds.
  • Invalidate board order after item creation or move-to-end; retry does not change rank.
  • Keep asset deletion’s existing mutation and invalidation behavior.

Scroll controller

  • Before background reorder, record topmost visible task ID and its relative top.
  • After commit, restore that relative top in useLayoutEffect.
  • Set a one-shot “explicit move” cause so move-to-end skips anchor restoration.
  • Use stable task IDs as React keys; never index keys.
  • Blur/focus deliberately to prevent browser focus scrolling.

Manager hold lifecycle

  • Manager button enters pending state while acquiring the hold.
  • Open the conversation only after successful acquisition.
  • On manager-to-manager switch: acquire new hold, switch chat, then release old hold.
  • Release on role/worker selection, dismiss, unmount, and page exit; TTL remains the crash safety net.

11. Recommended delivery phases

Land vertical slices in an order that does not force the frontend to depend on temporary client-only semantics.

1

Schema and domain model

Add priority, queue rank, asset category, manager hold storage, and item edit-lease storage. Reset and reseed dummy PuppyGarden data separately.

2

Dashboard read model

Return task metadata, all active items, recent global done items, recent per-worker done items, workers, and assets. Exclude cancelled items.

3

Queue-order mutations

Rank new tasks/items, implement move-to-end, preserve gap/tie semantics, and update board listing order.

4

Safe editing and assignment

Add item edit leases, atomic instruction/payload updates, worker transfer, cancellation consistency, and retry behavior.

5

Manager inspection hold

Add tokenized expiring holds, dispatcher enforcement, wake-up behavior, and lifecycle endpoints.

6

Frontend data layer

Update TypeScript models, API calls, hooks, query invalidation, fixtures, and error handling.

7

Task-card composition

Build header, editable goal, Markdown Overview, 2×2 metadata, task items, and unclipped Assets/Workers column.

8

Chat, filtering, and scrolling

Wire Manager/Worker targets, role dismissal, manager hold lifecycle, shared transcript behavior, bounded done filtering, background anchors, and explicit move replacement.

9

Assets, tests, and documentation

Add category stacks, retain title/X behavior, complete regression coverage, update API reference and Task Manager Markdown guidance.

12. Verification plan

Backend and store tests

  • Priority accepts only 0–3 and round-trips through create, patch, list, and dashboard.
  • New tasks and new items advance rank; unrelated edits do not.
  • Move-to-end changes only the selected task and tolerates rank gaps/duplicates.
  • Dashboard returns all active items plus at most three done globally and per worker.
  • Cancelled items are removed from the dispatchable queue and absent from user-facing reads.
  • Item edit lease loses to an already-dispatched item with a conflict.
  • Held FIFO item blocks later task items while earlier items still dispatch.
  • Instruction save updates the task item and queued payload atomically.
  • Worker reassignment atomically transfers queued work.
  • Manager hold blocks new manager dispatch, not an in-flight turn or worker queues.
  • Manager hold expiry/release wakes the queue and preserves prior manual pause/halt state.
  • Asset category defaults to other and round-trips.

Frontend tests

  • The existing global left sidebar and Sessions navigation remain visible and functional on PuppyGarden.
  • Multiple large task cards render in rank order.
  • Overview renders nested Markdown safely; raw HTML is not executed.
  • Metadata remains 2×2 and Manager is keyboard-accessible and visibly interactive.
  • Created uses created_at; priority renders as P0–P3.
  • Goal editing saves, cancels, and rolls back on failure.
  • Worker selection filters active and three recent done items for that worker.
  • No worker selection shows active and three recent done items across the task.
  • Cancelled items never render.
  • “No worker specified” is a placeholder, not a dropdown option.
  • Opening item editors acquires a hold; save/cancel releases it.
  • Manager chat opens only after its queue hold is acknowledged.
  • Worker chat selection does not change regular ChatPage queued messages.
  • Sidebar and full ChatPage show the same persisted transcript in both directions.
  • Ordinary card click returns to the previously selected Secretary/Broker role.
  • Background reorder preserves the topmost visible card.
  • Explicit move-to-end lets the successor replace the moved card, including when two cards are visible.
  • Focus does not scroll to the moved card at the bottom.
  • Asset stacks are expanded, title opens the URL, and × removes the asset.
  • Assets/Workers column remains visible with global chat open at supported widths.

Manual acceptance walkthrough

  1. Open PuppyGarden and confirm the existing global left sidebar, Sessions list, and navigation still work unchanged.
  2. Open a board with at least four tasks and two visible cards.
  3. Edit a goal and confirm the task does not reorder.
  4. Open queued instructions and confirm that item does not dispatch while earlier work can continue.
  5. Select a worker and confirm task-item filtering plus shared worker chat history.
  6. Select Manager and confirm its queue is held before chat opens; leave and confirm dispatch resumes.
  7. Switch Secretary/Broker and confirm later dismissal returns to the chosen role.
  8. Create a task item and confirm the task ranks to the front without moving the card being read.
  9. Move the upper visible card to the end and confirm the next card replaces it without animated scrolling.
  10. Move the lower visible card and confirm the upper card remains stationary.
  11. Cancel an item and confirm it disappears immediately and cannot be edited.
  12. Select all/individual workers and confirm no more than three done items appear in either scope.
  13. Open and remove assets from always-expanded category stacks.
